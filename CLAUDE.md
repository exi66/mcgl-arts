# starter — notes for the agent

Template repo for static GitHub Pages projects: Vite + React 19 + TS + Tailwind 4 + shadcn. It also hosts the
shadcn registry with the shared theme (`registry.json` → `https://exi66.github.io/starter/r/theme.json`).
UI text and user docs are in Russian.

## Which repo am I in

- **The starter itself** (`registry.json` exists): keep it generic — no project-specific code. Theme changes go
  into the `theme` item of `registry.json`, then are applied here with
  `pnpm registry:build && pnpm dlx shadcn@latest add ./public/r/theme.json --overwrite`.
- **A project made from the template** (no `registry.json`): the theme comes from `@exi/theme`. Never edit the
  theme parts of `src/index.css` (`:root`, `.dark`, `@theme inline`, `@layer base`) by hand; change them in the
  starter and reinstall with `pnpm dlx shadcn@latest add @exi/theme --overwrite`. Project-only CSS goes below.

## Commands

```
pnpm dev | build | preview | test | typecheck | lint | format | format:check | registry:build
```

Check every change with `pnpm lint && pnpm format:check && pnpm typecheck && pnpm test && pnpm build` (what CI runs).

## Rules

- **shadcn components are generated, never hand-written or edited.** Add them with
  `pnpm dlx shadcn@latest add <name>` (preset `b5KtPvff6`, style `base-sera`, Base UI primitives) into
  `src/components/ui/` (excluded from lint and prettier). Own components live in `src/components/`.
- Theme: `ThemeProvider` (`src/components/theme-provider.tsx`, generated by `shadcn init`) stores
  `light | dark | system` in localStorage `theme` and sets the class on `<html>`; the inline script in
  `index.html` applies it before the first paint. All projects on the same domain share this key on purpose.
- Settings: `useStored(key, init, { schema, override })` (`src/hooks/use-stored.ts`) → localStorage
  `<APP_NAME>:<key>` (`src/lib/app.ts`). Shared keys (`theme`, `i18nextLng`) are listed in `src/lib/storage.ts`.
  Pass a zod `schema` for anything non-trivial: stored values outlive code changes.
- i18n: every user-facing string goes through `t()` (react-i18next) in components and `i18next.t()` in plain TS
  (errors, workers…). Source language is `src/messages/ru.json`; keys are typed from it. Languages are discovered
  from `src/messages/*.json`: a file with strings must have every key of ru.json (plural forms may differ — ru
  `_one/_few/_many/_other`, en `_one/_other`), an empty file (`{}`) is a placeholder and the language is not offered
  until it is filled; `test/messages.test.ts` checks both. Strings that are content rather than UI (game data, text
  meant for a Russian forum) stay as they are — decide per project and note it in its CLAUDE.md.
- `src/lib/i18n.ts` is shared by every project: keep it identical to the starter's. It reads the shared
  `i18nextLng` (a choice made in any project), falls back to `ru` for a language the project lacks, and never writes
  the key on its own — only `setLanguage()` (the language toggle) does, so projects with fewer languages do not
  overwrite the user's choice. Tests initialise it via `setupFiles` in `vite.config.ts`.
- `useStored` and `src/lib/storage.ts` take any Standard Schema validator; its type is the local
  `src/lib/standard-schema.ts` (copied from the spec), so they do not depend on zod or ky.
- After `pnpm add`, check `pnpm-workspace.yaml`: pnpm 12 may silently add `minimumReleaseAgeExclude` entries for
  versions younger than a day. Remove them and use an older version (lower the range) instead.
- Validation: zod. HTTP: ky via `api` from `src/lib/api.ts` (`api.extend({ baseUrl })` per API); validate responses
  with `.json(schema)`, never trust a raw `.json()` from an external API.
- `src/index.css` is in `.prettierignore` on purpose: the shadcn CLI matches existing rules by text, so reformatted
  selectors would be added again on every theme update.
- Brand gradient (from the theme): `bg-brand-gradient` (with `text-brand-gradient-foreground` — white text on it fails
  contrast) and `text-brand-gradient` (needs a text-width element, e.g. `w-fit`).
- Page meta (`<title>`, description, Open Graph for link previews) is filled from `.env` (`VITE_SITE_URL`,
  `VITE_SITE_TITLE`, `VITE_SITE_DESCRIPTION`) via Vite's `%VAR%` replacement in `index.html`; preview image
  `public/og.png` (1200×630). `VITE_SITE_URL` must be the absolute deployed URL with a trailing slash.
- `vite.config.ts` uses `base: './'`, so the build works under any `/<repo>/` path.
- Dependency updates: Renovate. `default.json` (starter only) is the shared preset; every repo has `renovate.json`
  extending `github>exi66/starter`. Change rules in `default.json`, not per project.
- Deploy needs two repo settings besides the workflow: Pages source "GitHub Actions" and a `v*` tag rule in the
  `github-pages` environment (otherwise the deploy job is rejected for tags).
- Repo settings are not copied from the template. For a new project (`<repo>` = its name): Pages source, `v*` tag
  rule, auto-merge, and two rulesets on the default branch — no force-push/deletion (no bypass) and the `check`
  status required (admins bypass, so the owner still pushes directly; Renovate PRs wait for CI):
  ```
  gh api -X POST repos/exi66/<repo>/pages -f build_type=workflow
  gh api -X POST repos/exi66/<repo>/environments/github-pages/deployment-branch-policies -f name='v*' -f type=tag
  gh repo edit exi66/<repo> --enable-auto-merge --delete-branch-on-merge
  gh api -X POST repos/exi66/<repo>/rulesets --input - <<< '{"name":"main: no force-push or deletion","target":"branch","enforcement":"active","conditions":{"ref_name":{"include":["~DEFAULT_BRANCH"],"exclude":[]}},"rules":[{"type":"deletion"},{"type":"non_fast_forward"}]}'
  gh api -X POST repos/exi66/<repo>/rulesets --input - <<< '{"name":"main: CI must pass","target":"branch","enforcement":"active","conditions":{"ref_name":{"include":["~DEFAULT_BRANCH"],"exclude":[]}},"bypass_actors":[{"actor_id":5,"actor_type":"RepositoryRole","bypass_mode":"always"}],"rules":[{"type":"required_status_checks","parameters":{"strict_required_status_checks_policy":false,"required_status_checks":[{"context":"check","integration_id":15368}]}}]}'
  ```
  The `github-pages` environment appears after the Pages call; run the tag-rule line after it.
- `README.md` is a short usage guide for people; implementation details belong here.
- Commit only when asked. CI runs on pushes/PRs to `main`; tags `v*` deploy to GitHub Pages
  (`.github/workflows/pages.yml`, runs CI first).
- Package manager: pnpm.

## This project: mcgl-arts

Gallery of pixel art from Minecraft Galaxy (https://exi66.github.io/mcgl-arts/).

- Artworks: `src/assets/artworks/<Author>/<Title>.png|jpg|jpeg`, folder `default` = no author. Collected with
  `import.meta.glob` in `src/lib/gallery.ts`; the author comes only from the folder name.
- **Artwork URLs are permanent**: the forum links to them. `assetFileNames` in `vite.config.ts` keeps
  `artworks/<Author>/<Title>.png` without a hash, and `assetsInlineLimit: 0` keeps small images as files. Never rename
  or move an artwork file without a reason; check `dist/artworks/` after build changes.
- Deploy: besides `v*` tags (code changes), `pages.yml` deploys on a push to `main` that touches
  `src/assets/artworks/**`, so a new picture goes live without a release. The `github-pages` environment therefore
  allows both the `main` branch and `v*` tags.
- Viewer: viewerjs, pinned; `src/lib/viewer.ts` patches its internal `initImage` (integer upscaling of small pixel art).
  Renovate does not automerge it — check the viewer by hand on update.
- Search (`src/lib/search.ts`, tests in `test/search.test.ts`): `name:` / `author:` operators, the query is kept in `?q=`.
- i18n: only Russian, like mcgl-shcematica-viewer: `src/messages/en.json` is an empty placeholder and there is no
  language toggle; filling en.json (every key of ru.json) enables English — then add a toggle calling `setLanguage()`.
  Artwork titles and author nicks are content and are never translated; only UI strings go through `t()`.
- Header brand: the project favicon (`public/favicon.svg`) + title, not the exi.moe logo.
